## 1. 已确认的 6 个决策

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 仓库形态 | 单仓 + npm workspaces |
| 2 | 服务端语言 | TypeScript |
| 3 | Web 框架 | Fastify 5 |
| 4 | SDK 签名 | 内联纯 JS HMAC-SHA256（+约 2KB gzip），同步可算，保住 `sendBeacon` 路径 |
| 5 | 进程形态 | 单进程 `START_MODE=all`，支持 `ingest` / `api` 一键拆分 |
| 6 | SDK 目录 | 迁入 `packages/sdk-web`，版本升 2.1.1 |

## 2. 仓库结构

```
event-tracking-analysis-system/
├── package.json                     # workspaces 根，只放聚合脚本
├── docker-compose.yml               # track-server + mysql
├── docs/
├── packages/
│   ├── sdk-web/                     # 前端埋点 SDK（原有代码迁入）

│   └── analytics-web/               # 分析后台 Vue3（下一批，暂不创建）
```

**不建 `packages/shared`**：MVP 仅事件常量需要跨包共享，建共享包要额外维护 TS 构建链路，成本大于收益。事件常量先放 `track-server/src/domain/events.ts`，等 `analytics-web` 落地时再抽。

### 3.1 必要的 4 处改造（对应架构文档 4.6）

| # | 改造 | 目的 |
|---|---|---|
| 1 | `buildBatchPayload(records, batchId)` 支持外部传入 batchId；`persistFailedBatch` 冻结 batchId，`resumeFailedBatches` 复用之 | 补发幂等，避免重复入库 |
| 2 | `fetchReport` 对 4xx 短路（不重试、不持久化），仅 5xx / 网络错误重试 | 避免永久性失败无限重试 |
| 3 | 请求头补 `X-Track-App-Id` / `X-Track-Sent-At` / `X-Track-Sign`（HMAC-SHA256） | 服务端验签、时间窗防重放 |
| 4 | payload 顶层补 `env` 字段（`test` / `prod`），由构建注入 | 测试数据不污染生产漏斗 |

签名原文：`HMAC_SHA256(secret, appId + "." + sentAt + "." + rawBody)`，输出小写 hex。

### 4.1 请求处理链路

```
POST /api/track
  → raw-body        text/plain → 原始字符串（不猜 Content-Type）
  → 限流            IP / appId 固定窗口，超限 429
  → 验签            appId 白名单 → sentAt ±5min → HMAC 比对
  → ingest.service  JSON.parse → zod 批次校验 → 上限校验
                    → batch.repo.insertIfAbsent()  冲突 → 200 duplicate
                    → 逐条归一化（非法条目跳过并计数）
                    → event.repo.bulkInsert()      与幂等表同事务
  → error-handler   DB 失败 → 503；其余拒绝 → 200 + rejected 日志
```

### 4.2 Node 栈的隔离方式（替换架构文档的"线程池"表述）

Node 是单线程，慢聚合查询会阻塞事件循环，直接拖慢埋点接口。隔离手段：

1. **两个独立连接池**：`DB_POOL_INGEST=10` / `DB_POOL_QUERY=5`
2. 聚合 SQL 带 `/*+ MAX_EXECUTION_TIME(5000) */` 提示 + 应用层超时兜底
3. 需要更强隔离时 `START_MODE=ingest|api` 拆成两进程，镜像不变

### 4.3 关键实现约束

- 幂等表与事件表**同事务**，否则幂等表写了、事件没写，该批永久丢失
- 单条记录非法**只跳过该条**，不得整批失败
- 被拒绝 / 重复批次都返回 **200**，否则 SDK 会无限重试
- `properties` 长度、各 VARCHAR 字段长度必须截断，否则插入报错
- `mysql2` 连接池设 `timezone: 'Z'`，所有 DATETIME 按 UTC 读写

## 5. 技术选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 20 LTS（本机 22 亦可） | SDK 已要求 ≥18 |
| 框架 | Fastify 5 | 内置 pino、`app.inject()` 便于测路由，高频小请求性能好 |
| 语言 | TypeScript（ESM + NodeNext） | batch 多态结构，类型能挡住大部分错误 |
| 校验 | zod 3 | 运行时校验 + 类型推导一体 |
| DB | mysql2/promise + 手写 SQL | 只有 2 张表 + 少量聚合，ORM 是负担 |
| 迁移 | SQL 文件 + 轻量 runner | 不引入 Prisma/Drizzle 迁移体系 |
| 配置 | dotenv + zod | 启动即校验 |
| 日志 | pino | 结构化，rejected 日志可直接检索 |
| 测试 | vitest（服务端）/ node:test（SDK 不动） | 服务端依赖注入，测试不连真库 |
| 容器 | 多阶段 Dockerfile + compose | 仅 server + mysql |

## 6. 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/track` | 埋点接收（唯一写入入口） |
| GET | `/api/funnel` | 漏斗各步人数与转化率 |
| GET | `/api/funnel/sessions` | 某步流失会话列表（下钻） |
| GET | `/api/funnel/session/:sessionId` | 单会话完整事件序列 |
| GET | `/api/overview/events` | 事件量 / 独立用户数趋势 |
| GET | `/api/meta/funnels` | 漏斗列表（前端渲染选择器） |
| GET | `/api/experience/performance` | 性能指标分位数 + 按页面/国家/设备分组 |
| GET | `/api/experience/stay` | 停留时长分位数 + 按页面/结束原因分组 |
| GET | `/api/meta/integrity` | 批次声明条数 vs 实际入库行数 |
| GET | `/healthz` `/readyz` | 存活 / 就绪（readyz 探 DB） |

> 漏斗与概览接口额外支持 `country`（ISO 两位码）与 `deviceType`（desktop/mobile/tablet）筛选。

### 9.1 页面能力

| 页面 | 内容 |
|---|---|
| 转化漏斗 | 首步/末步会话数、整体转化率、最大流失环节；漏斗图；分步表格（到达数、相对上一步、总转化率、流失数）；点色块或行打开流失会话抽屉，抽屉内可继续看单会话事件轨迹 |
