## 2. 背景与目标

公司此前缺少统一的前端埋点 SDK，各系统重复实现行为采集、性能监控与错误上报，口径不一致且数据不可靠。本 SDK 提供一套可复用、零依赖、单文件可嵌入的浏览器端采集能力。

本期目标：

1. 接入成本降到「粘贴一段 `<script>`、只填 appId」，无需配置上报地址与环境。
2. 覆盖业务事件、Web Vitals、页面停留、点击、错误五类采集，统一批次协议上报到 `POST /api/track`。
3. 在网络失败、页面卸载、服务端限流等场景下通过重试、降级与补发降低数据丢失率，同时避免永久性失败造成无限重试。
4. 提供采样、URL 脱敏、退出采集等隐私与成本开关。

本期范围（已实现）：脚本标签与构造函数两种接入形态、四类记录上报、三通道传输与失败补发、可选请求签名、会话与实例管理、生命周期清理、42 个自动化用例。

本期明确不做：服务端埋点 SDK（由 `packages/track-server` 提供通用 HTTP 接口）、数据查询与看板（由 `packages/analytics-web` 提供）、多语言 SDK、离线无限量队列（失败落盘上限 5 批）、前端密钥加密存储（脚本标签形态本身不携带密钥）。

## 4. 业务流程

**FLOW-001 脚本标签初始化**：页面在加载 SDK 前向 `window.__trackQueue` 写入 `init` 指令与待发送事件 → SDK 加载后自动扫描队列，取 `init` 参数构造实例 → 回放其余 `track` / `trackEvent` / `flush` 指令 → 原队列被替换为即时转发器，并暴露 `.instance` → 重复加载同一脚本时直接复用已有实例。

**FLOW-002 事件入队与批量上报**：采集入口产生记录 → `report()` 依次检查销毁态、浏览器环境、总开关、退出采集、采样 → 通过则做数据快照并写时间戳 → 入内存队列（超出上限丢弃最旧）→ 达到批量大小立即发送，否则启动定时发送 → `buildBatchPayload()` 收敛公共字段并生成批次标识 → 进入三通道传输。

**FLOW-003 传输、降级与补发**：页面隐藏或强制 beacon 时优先 `sendBeacon` → 否则走 `fetch`（带指数退避与抖动重试）→ 仍失败降级 `XMLHttpRequest` → 全部失败且开启持久化时写入本地存储，下次启动先清空再按原批次标识补发。4xx 视为永久性失败直接终止，不重试也不落盘。

**FLOW-004 性能指标两阶段**：页面 load 后采集导航计时与 FCP 并以 `stage=load` 上报 → 页面隐藏、卸载或实例销毁时以 `stage=final` 上报 LCP、CLS、INP、FID、长任务与资源明细 → 断开相关 observer，最终指标只上报一次。

**FLOW-005 页面停留与路由切换**：页面可见时开始累计可见态时长 → 页面隐藏或路由变化时分段结算并重置起点 → 分段时长不足 1 秒不上报 → SPA 路由通过包装 `pushState` / `replaceState` 与监听 `popstate` 感知变化 → 实例销毁时还原被包装的原生方法。

**FLOW-006 错误采集与限流**：监听全局错误、未处理拒绝与资源加载失败 → 归一化错误要素并脱敏链接 → 按错误特征去重（5 秒窗口）与计数限流（单页 50 条）→ 通过限流的错误进入统一入队流程。

## 5. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 默认配置为：`batchSize=10`、`batchTimeout=5000ms`、`maxRetries=3`、`retryDelay=1000ms`、`maxQueueSize=200`、`sampleRate=1`、`contentType='text/plain;charset=UTF-8'`、`persistFailed=true`。 |
| BR-002 | 配置读取仅把 `undefined` 与 `null` 当作缺省；`0` 是合法值。类型非法直接抛错；`sampleRate` 超出 `[0,1]`、`batchSize` 小于 1、`batchTimeout` / `retryDelay` / `maxRetries` 小于 0、`maxQueueSize` 小于 1 均抛错。 |
| BR-003 | 更新配置先校验后赋值，校验失败保留原配置；切换性能、错误、资源、点击或总开关时，先拆除监听再重新初始化。 |
| BR-004 | 采样在实例创建时判定一次，并在每条记录入队前再次判定；采样率为 0 时全量不采集；手动事件与自动事件受同一采样控制。 |
| BR-005 | 会话标识格式为 `sess_<毫秒时间戳>_<9 位随机段>`；无操作 30 分钟视为过期并更换标识；每次记录上报会尝试刷新活跃时间，刷新按 5 秒节流。 |
| BR-006 | 同一批次内公共字段只出现一次：`appId`、`sdkVersion`、`userId`、`sessionId`、`batchId`、`sentAt`、`env`、`context`；明细放在 `batch` 数组。 |
| BR-007 | 批次数据在发送前只序列化一次，三个传输通道共享同一份字符串与签名，避免各通道重复生成批次标识。 |
| BR-008 | 内存队列上限 200 条，超出时丢弃最旧记录并累计丢弃计数；队列长度达到 10 条立即发送。 |
| BR-009 | 传输优先级为 `sendBeacon` → `fetch` → `XMLHttpRequest` → 本地落盘；仅当页面隐藏或显式指定时使用 beacon。 |
| BR-010 | beacon 载荷超过 60 KB 时不拆分，直接降级到 fetch；`sendBeacon` 返回 `true` 只代表浏览器已接收入队，不代表服务端入库成功。 |
| BR-011 | 重试总请求次数为 `maxRetries + 1`；退避延迟为 `min(round(retryDelay × 2^attempt × jitter), 30000ms)`，抖动系数取自 `[0.5, 1)`；最后一次失败不再等待。 |
| BR-012 | 4xx 响应视为永久性失败：fetch 返回丢弃状态、XHR 直接成功返回，均不重试、不降级、不落盘；5xx 与网络错误进入重试。 |
| BR-013 | 全通道失败且开启持久化时，保存 `{ts, batchId, records}` 到本地存储，最多保留 5 批并丢弃最旧；下次初始化先清空存储再按原批次标识逐批补发。 |
| BR-014 | 签名原文为 `HMAC_SHA256(signSecret, appId + '.' + sentAt + '.' + rawBody)`，输出小写 hex；fetch 与 XHR 通过 `X-Track-App-Id` / `X-Track-Sent-At` / `X-Track-Sign` 请求头传递，beacon 降级为同名 query 参数。 |
| BR-015 | 性能指标分两阶段：`load` 阶段上报导航计时与 FCP，`final` 阶段上报 LCP、CLS、INP、FID、长任务与资源明细；最终指标只上报一次。 |
| BR-016 | CLS 采用最大 session window 算法：相邻布局偏移间隔超过 1 秒或窗口超过 5 秒则重开窗口，结果保留 4 位小数；INP 按交互分组取最大时长再取第 98 百分位。 |
| BR-017 | 资源监控默认关闭；开启后只采集耗时超过 100ms 的资源；长任务与资源明细采集上限 100 条、上报明细上限 20 条。 |
| BR-018 | 页面停留只统计可见态分段，分段不足 1 秒不上报；路由变化会先结算上一页再重置计时；同一时刻的卸载与隐藏事件只结算一次。 |
| BR-019 | 点击采集使用捕获阶段事件委托并向上查找带 `data-track` 的元素，不做节流；元素路径最多保留 3 个类名；文本截断 100 字符。 |
| BR-020 | 错误按特征串在 5 秒内去重，单页最多上报 50 条；堆栈截断 2000 字符；非字符串拒绝原因归一化为消息、名称与堆栈。 |
| BR-021 | URL 脱敏默认开启：移除 `#` 及后续内容，对 query 中命中敏感名单的参数值替换为三个星号并保留参数名；退出采集状态持久化到本地存储并在开启时清空待发队列。 |
| BR-022 | 服务地址缺省时按 SDK 自身脚本标签所在域推导 `<域>/api/track`；构造函数显式传入的服务地址优先级最高，其上携带的 `appId` 与 `env` 查询参数可作为配置来源。 |

## 6. 数据规则

批次公共字段与明细结构：

| 层级 | 字段 | 说明 |
| --- | --- | --- |
| 批次 | `appId` / `sdkVersion` / `userId` / `sessionId` / `batchId` / `sentAt` | 会话与批次标识在批次层出现一次 |
| 批次 | `env` | 配置为空时不输出该字段，由服务端按 appId 判定环境 |
| 批次 | `context` | `url`（脱敏后）、`referrer`（脱敏后）、`title`、`userAgent`、`language`、`screen`、`viewport`、`devicePixelRatio` |
| 明细 | `type` / `timestamp` / `data` | 每条记录独立携带类型与客户端时间戳 |

四类记录的 `data` 结构：

| 类型 | 数据内容 |
| --- | --- |
| `event` | `{ event, properties }`，属性入队时做快照 |
| `performance` | `load` 阶段含导航计时与 FCP；`final` 阶段含 FCP、LCP、CLS、INP、FID、长任务计数与明细、资源明细、触发原因 |
| `page_stay` | `{ stayTime, totalStayTime, trigger, page, referrer }`，`trigger` 取 `hidden`、`beforeunload`、`pagehide`、`route_change` |
| `error` | `javascript`、`promise`、`resource` 三类，分别携带消息、位置、堆栈或资源地址 |

字段约束：事件名为非空字符串，否则不入队；所有上报链接先脱敏；SDK 不额外采集键盘输入、表单明文、完整手机号与证件号；敏感参数名单覆盖令牌、授权、密码、密钥、签名、会话、手机号、邮箱、证件号与票券类字段。

## 7. 接口清单

公开 API：

| 方法 | 说明 |
| --- | --- |
| `new TrackerSDK(options)` | 创建实例并自动初始化；已有运行实例时给出告警 |
| `track(name, properties, options)` | 上报业务事件，`options.immediate` 为 true 时跳过批量等待 |
| `trackEvent(name, properties)` | 与 `track` 等价，无立即发送参数 |
| `flush(options)` | 立即发送队列，`{ beacon: true }` 强制走 beacon |
| `report(type, data)` | 上报自定义类型记录，数据入队时做快照 |
| `updateConfig(partial)` | 合并配置，校验失败不污染原配置；开关变化重建监听 |
| `getConfig()` | 返回配置副本及版本、会话、采样与退出状态 |
| `setOptOut(bool)` / `isOptedOut()` | 退出或恢复采集，状态持久化 |
| `destroy()` | 上报最终指标、发送队列、移除监听、断开 observer、还原路由包装 |
| `TrackerSDK.getInstance(options)` | 复用未销毁的既有实例 |
| `TrackerSDK.version` | 版本号常量 |

上报接口契约：`POST /api/track`，请求体为批次 JSON；默认 `Content-Type` 为 `text/plain;charset=UTF-8` 以规避跨域预检；服务端需按原始请求体解析并允许 `POST`；重复投递由服务端按批次标识去重。

## 8. 页面与交互

SDK 本身不提供界面，与页面的交互通过以下入口完成：

- 脚本标签：页面写入 `window.__trackQueue.push(['init', { appId }])` 后异步插入 `id="track-sdk"` 的脚本；也可直接用 `<script id="track-sdk" data-app-id="…" src="…">` 免队列初始化。
- 属性埋点：在元素上声明 `data-track="事件名"`，点击元素或其子节点即产生事件。
- 本地示例：`example.html` 与 `demo.html` 提供可直接打开的接入示例。
- 调试输出：`debug=true` 时控制台打印初始化与上报日志，不改变上报行为。

## 10. 异常与边界

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| EX-001 | 配置项类型非法或取值越界 | 构造与更新配置时抛错；更新失败保留原配置 |
| EX-002 | 缺少 appId | 构造时给出控制台告警，不阻断初始化 |
| EX-003 | 采样未命中或总开关关闭 | 不注册任何采集监听，所有上报入口返回失败状态 |
| EX-004 | 浏览器环境不支持相关 Web API | 对应监控跳过注册，不影响其他采集与上报 |
| EX-005 | 事件名为空或非字符串 | 直接返回失败状态，不入队 |
| EX-006 | 内存队列已满 | 丢弃最旧记录并累计丢弃计数 |
| EX-007 | beacon 载荷超过 60 KB | 放弃 beacon，降级到 fetch |
| EX-008 | 服务端返回 4xx | 判定为永久性失败，停止重试、降级与落盘 |
| EX-009 | 服务端返回 5xx 或网络中断 | 按退避公式重试，耗尽后降级 XHR，仍失败则落盘 |
| EX-010 | 本地存储不可用或内容损坏 | 探针检测后跳过持久化；解析失败按空列表处理 |
| EX-011 | 补发再次失败 | 按原批次标识重新写回本地存储，等待下次启动 |
| EX-012 | 页面长时间不隐藏 | 最终性能指标不会产生，只有 load 阶段数据 |
| EX-013 | 同一脚本被重复加载 | 检测到队列已有实例时直接返回，避免重复注册 |
| EX-014 | 卸载与隐藏事件同时触发 | 通过已处理标志确保停留时长只结算一次 |
| EX-015 | 路由包装被其他脚本覆盖 | 仅在原生方法仍是本 SDK 包装函数时还原，避免误还原 |
| EX-016 | 实例销毁后仍有事件触发 | 监听已全部移除，上报入口以销毁态直接返回 |

## 11. 验收标准

### AC-001 脚本标签接入
- 给定 页面中写入了带 appId 的全局指令队列，随后异步插入脚本标签；
- 当 SDK 加载完成并回放队列；
- 则 自动创建实例，队列中的事件全部进入上报流程，且队列被替换为可即时转发的实例队列。

### AC-002 构造函数接入与配置校验
- 给定 调用方传入合法的服务地址、appId、环境、采样率与功能开关；
- 当 构造 SDK 实例；
- 则 配置被完整读取，自动采集监听按开关注册；若采样率传字符串，则构造直接抛错而不是静默回退。

### AC-003 零值与非法值处理
- 给定 采样率设为 0、批量超时设为 0、批量大小设为 0 三种配置分别传入；
- 当 实例初始化；
- 则 前两种配置生效且采样率为 0 时全量不上报，批量大小为 0 时抛错。

### AC-004 手动事件与立即发送
- 给定 实例已完成初始化且采样命中；
- 当 分别调用 `track`、`trackEvent` 以及带立即发送参数的 `track`；
- 则 前两者产生结构一致的事件记录并按批量节奏发送，第三者跳过批量等待立即发送。

### AC-005 自动点击采集
- 给定 按钮内嵌图标与文本节点且按钮声明了 `data-track`；
- 当 在 100ms 内连续点击图标与文本；
- 则 两次点击均产生事件记录，事件名为按钮上的属性值，记录包含元素路径、点击坐标与视口尺寸。

### AC-006 性能指标分阶段
- 给定 页面包含图片与脚本资源并发生布局偏移与用户交互；
- 当 页面加载完成，随后页面切换到隐藏状态；
- 则 先产生一条含导航计时与 FCP 的加载阶段记录，再产生一条含 LCP、CLS、INP、FID 与长任务的最终阶段记录，且最终阶段记录只出现一次。

### AC-007 页面停留计时
- 给定 页面可见 3 秒后隐藏 1 秒再可见 2 秒，随后发生一次前端路由跳转；
- 当 各状态切换完成；
- 则 产生分段停留记录，不足 1 秒的隐藏段不计入，路由跳转产生一条带路由原因的记录并按新页面重置累计时长。

### AC-008 错误去重与限流
- 给定 同一错误在 5 秒内连续抛出 100 次；
- 当 错误监听持续触发；
- 则 只产生 1 条错误记录；当不同错误累计超过 50 条时，后续错误全部丢弃。

### AC-009 上报降级与幂等补发
- 给定 fetch 连续返回 5xx，且 localStorage 可写；
- 当 队列触发发送；
- 则 请求按退避公式重试后降级到 XHR，全部失败后写入本地存储并保留原批次标识；下次初始化时先清空存储再以同一批次标识补发。

### AC-010 永久性失败短路
- 给定 服务端对上报请求返回 4xx；
- 当 队列触发发送；
- 则 只产生 1 次请求，不进入重试与 XHR 降级，也不写入本地存储。

### AC-011 请求签名
- 给定 实例配置了非空签名密钥；
- 当 分别通过 fetch 与页面隐藏时的 beacon 发送批次；
- 则 fetch 请求携带三个签名头，beacon 请求携带同名查询参数，两者签名均可按约定原文重新计算得到相同结果。

### AC-012 隐私与生命周期
- 给定 页面链接包含令牌参数与片段标识，实例已采集 3 条事件并停留在待发队列；
- 当 调用退出采集接口，随后调用销毁接口；
- 则 链接中的令牌参数被替换为掩码且片段被移除，退出状态被持久化，待发队列被清空；销毁后所有监听被移除、路由包装被还原、后续上报入口返回失败状态。

## 12. 非功能需求

- **体积**：单文件 UMD，无运行时依赖；内联同步 HMAC 实现未压缩约 4 KB、gzip 后约 2 KB；发布产物经压缩工具二次压缩与混淆后托管在 `dist/track-sdk.min.js`。
- **性能**：点击采集不做节流；队列达到 10 条或 5 秒即发送；资源与长任务明细按上限裁剪；URL 脱敏与快照在入队时同步完成。
- **兼容性**：Node.js 18 及以上用于构建与测试；浏览器目标为主流版本与仍在维护的版本；提供 CommonJS、AMD 与浏览器全局三种导出。
- **可维护性**：单一源码文件配合 42 个自动化用例；构建前执行代码检查、测试与压缩；压缩产物可复用同一套用例回归。
- **隐私**：默认开启链接脱敏与会话持久化；退出采集状态本地持久化；不采集表单明文输入。

## 13. 依赖与风险

| 项 | 说明 |
| --- | --- |
| 服务端依赖 | 必须存在可用的 `POST /api/track` 接口；服务端需按原始请求体解析、返回允许跨域的响应头并按批次标识去重 |
| 域名依赖 | 脚本标签形态按 SDK 自身脚本所在域推导上报地址；若静态资源域与采集域不同，需显式传服务地址，否则数据不会进入本系统看板 |
| 浏览器 API | `PerformanceObserver`、`sendBeacon`、`localStorage` 在部分环境可能不可用；SDK 跳过对应能力但不中断其他采集 |
| 密钥暴露 | 脚本标签形态不携带密钥，防护退化为 appId 白名单与限流；需要签名时必须使用构造函数形态，且前端密钥本身仍可被逆向读取 |
| 指标时效 | 最终阶段指标依赖页面隐藏或卸载事件；长期不隐藏的标签页不会产生最终阶段数据 |
| 会话边界 | 会话加载与刷新对 30 分钟边界的判定方向不同，边界时刻可能出现一次会话标识差异 |
| 重试语义 | `sendBeacon` 返回成功不代表服务端入库成功；常规时段需通过 fetch 获取响应状态才能确认送达 |

## 14. 待确认问题

- 脚本标签形态是否需要支持签名密钥的安全传递方案（当前形态设计上不带签名）。
- 服务端已按 appId 判定环境后，SDK 侧是否继续保留显式环境配置，还是完全移除以避免误覆盖。
- 采样率在运行期更新时重新掷骰是否符合业务预期；是否需要改为只在实例创建时生效。
- 长任务与资源明细的上报条数上限是否需要按实际数据量调整。
- 缺少脚本标签且服务地址未配置时保留占位地址的行为，是否改为直接告警并停止初始化。
