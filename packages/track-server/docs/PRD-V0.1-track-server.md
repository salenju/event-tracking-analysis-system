| 项 | 内容 |

## 2. 背景与目标

前端 SDK 与后端业务需要一个统一的接收端点，把多应用多环境的事件写入同一份存储，并提供漏斗、概览与体验指标的查询能力。本期目标：提供一条高可用的写入链路（鉴权、限流、幂等、事务、返回码契约），以及三个只读查询域（漏斗、事件概览、体验指标）和配套的管理接口。

本期范围（已实现）：埋点接收接口、飞书与本地登录、应用与成员管理、漏斗配置与查询、流失会话下钻、事件概览、性能与停留指标、数据完整性对账、数据库迁移、容器构建、73 个测试用例。

本期明确不做：消息队列与缓存中间件、按天预聚合表、数据归档与删除接口、主动告警平台、GeoIP 反查、应用层查询超时定时器。数据保留与告警策略仅以结构化日志形式落地，不提供管理界面。

## 4. 业务流程

**FLOW-001 上报接收**：请求进入 → 原始报文读取 → IP 限流 → 空报文判定 → 应用鉴权 → 应用限流 → 解析客户端 IP、国家、地区与 UA → 批次校验与归一化 → 幂等表插入 → 事件批量插入 → 同事务提交 → 返回结果。任一步发生永久性失败时返回成功状态并记拒绝日志；仅数据库故障返回可重试状态。

**FLOW-002 失败与幂等**：同一批次标识重复投递时回滚事务并返回重复标记；网络失败后客户端用原批次标识补发，服务端按主键冲突识别重复；批次内单条记录非法时跳过该条并累计跳过计数，全部非法才拒绝整批。

**FLOW-003 漏斗查询**：读取漏斗配置并校验事件名 → 解析时间范围与筛选参数 → 按会话聚合各步骤首次出现时间 → 外层按相邻时间升序与窗口约束统计各步会话数 → 计算相对上一步与相对首步的转化率、流失数 → 按需查询流失会话列表与单会话事件时间线。

**FLOW-004 概览与体验查询**：按时间跨度选择小时或天粒度 → 按应用、环境、事件类型与时间范围聚合触发量与独立用户 → 性能与停留查询用窗口函数取分位数并按页面、国家、设备或结束原因分组 → 完整性查询对账批次数与事件行数。

**FLOW-005 登录**：生成一次性状态并跳转飞书授权页 → 回调时先消费状态 → 换取访问令牌并拉取用户信息 → 绑定用户并判定角色 → 签发会话令牌 → 二维码模式通过页面消息回传，授权模式通过地址片段回传。

**FLOW-006 应用管理**：管理员创建应用时生成随机应用标识与密钥 → 密钥明文只在响应中出现一次 → 列表只返回掩码 → 轮换与停用后缓存失效 → 环境变量来源的应用在页面上只读。

## 5. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 请求体上限 262144 字节，单批最多 50 条记录，单条属性序列化后最多 16384 字节；超限按永久性失败处理。 |
| BR-002 | `Content-Type` 为 `text/plain;charset=UTF-8` 时按原始报文解析 JSON，不依赖头部判断格式；同时接受 JSON 与表单格式的原始字符串。 |
| BR-003 | 签名为 `HMAC_SHA256(secret, appId + '.' + sentAt + '.' + rawBody)`，使用恒定时间比较；请求时间与服务端时间偏差超过 300 秒视为过期。 |
| BR-004 | 验签参数优先取请求头，缺失时回落到查询参数，以兼容无法设置自定义头的页面卸载通道。 |
| BR-005 | 关闭签名校验时只做应用白名单校验；应用停用按未知应用处理。 |
| BR-006 | 限流采用进程内固定窗口：单 IP 每分钟 600 次，单应用每分钟 3000 次；触发时返回 429 并带重试等待秒数。 |
| BR-007 | 永久性失败（未知应用、签名失败、时间窗超时、非法 JSON、载荷超限、字段非法、重复批次）统一返回成功状态并丢弃，避免客户端无限重试。 |
| BR-008 | 数据库不可用或写入超时返回 503，由客户端重试与本地补发；限流返回 429，其余查询类错误按标准状态码返回。 |
| BR-009 | 批次表与事件表在同一事务提交；主键冲突视为重复批次并回滚；写入失败回滚后异常上抛。 |
| BR-010 | 环境取值优先级为报文字段、查询参数、应用记录配置、服务端默认环境；查询侧按请求参数、漏斗配置、服务端默认的顺序取值。 |
| BR-011 | 批次级上下文包含 IP、国家、地区、UA、设备类型、操作系统、浏览器、页面路径、来源页与语言；国家码归一化为两位大写码，页面路径去除查询串。 |
| BR-012 | 记录类型共四种：业务事件、性能、页面停留、错误；只有业务事件参与漏斗与概览统计。 |
| BR-013 | 属性中的订单号、钱包类型、失败原因提升为独立列并兼容驼峰与下划线命名；各字段按列宽截断，空字符串写为空值。 |
| BR-014 | 客户端事件时间与服务端接收时间偏差超过 24 小时时，回退使用服务端时间作为事件发生时间。 |
| BR-015 | 漏斗步骤必须是在事件字典中登记过的事件名；配置步骤数量为 2 到 10，相邻窗口为 1 到 1440 分钟，默认 30 分钟。 |
| BR-016 | 漏斗以会话为统计主体，同一步骤重复出现只取首次时间；相邻步骤需按时间升序且间隔不超过窗口；钱包类型筛选只作用于首步之后的步骤。 |
| BR-017 | 漏斗转化率与流失数保留四位小数；流失会话按最后到达时间倒序分页，每页默认 20 条。 |
| BR-018 | 概览时间粒度按跨度自动选择：跨度不超过 48 小时按小时聚合，否则按天聚合；时间跨度上限 366 天；默认查询最近 7 天。 |
| BR-019 | 独立用户按应用、环境、事件与时间桶统计去重身份，未登录用户回退到会话标识；看板侧的独立用户为各时间桶求和而非全区间去重。 |
| BR-020 | 性能指标共六项：最大内容绘制、首次内容绘制、首字节时间、加载完成、交互响应延迟与累积布局偏移；分位数用行号加向上取整取第 N 个值，不做插值。 |
| BR-021 | 完整性报告按服务端接收时间对账，输出批次总数、声明条数、实际条数、缺失条数以及不一致批次列表。 |
| BR-022 | 登录状态一次性有效，有效期 5 分钟；会话令牌为 32 字节随机值，库中只存摘要；默认有效期 168 小时。 |
| BR-023 | 角色判定顺序为白名单应用标识、库中无可用管理员时首个登录者、其余默认普通成员；用户停用后已有令牌立即失效。 |
| BR-024 | 应用标识为随机前缀加 12 位十六进制字符，不含业务名称；密钥为 48 位十六进制字符；同一环境下应用名大小写不敏感且不可重复。 |
| BR-025 | 密钥缓存有效期 30 秒，未命中缓存 10 秒；新增、轮换、停用与删除后主动失效；数据库故障进入 5 秒冷却并使用环境变量兜底，无法兜底时上报接口返回 503。 |

## 8. 页面与交互（本服务无界面，以下为调用方交互契约）

本服务不提供页面，交互对象是前端 SDK、后端业务服务与分析看板。上报方以原始报文调用单一写入接口并按状态码决定是否重试；看板以 Bearer 令牌调用查询与管理接口；登录回调返回极简页面，用页面消息或地址片段把令牌交给前端。公开路径只有上报接口、健康检查、认证配置、本地登录与飞书回调。

## 11. 验收标准

### AC-001 正常上报入库
- 给定 应用已颁发且密钥有效，请求体包含一批合法的业务事件与性能记录；
- 当 客户端携带正确签名调用上报接口；
- 则 接口返回成功状态并给出批次标识与接收条数，批次表与事件表各出现对应记录，批次上下文包含解析后的国家与页面路径。

### AC-002 重复批次幂等
- 给定 同一批次标识已成功入库；
- 当 客户端以相同批次标识再次上报相同报文；
- 则 接口返回成功状态并带重复标记，事件表不新增记录，事务被回滚。

### AC-003 单条非法跳过
- 给定 一批五条记录，其中一条缺少事件名、一条属性超出单条上限；
- 当 该批次被上报；
- 则 接口返回成功状态，其余三条记录入库，跳过计数记录两条并标明原因。

### AC-004 永久性失败不重试
- 给定 客户端使用未知应用标识或过期时间戳上报；
- 当 服务端完成鉴权；
- 则 接口返回成功状态并给出对应原因，客户端不再进入重试流程，服务端输出一条结构化拒绝日志。

### AC-005 限流返回
- 给定 单一来源在固定窗口内已使用完应用额度；
- 当 该来源再次上报；
- 则 接口返回 429 并携带重试等待秒数，数据库不产生新记录。

### AC-006 数据库故障
- 给定 数据库连接不可用；
- 当 客户端上报合法批次；
- 则 接口返回 503，事务回滚，客户端依据状态码进入重试与本地补发。

### AC-007 漏斗计算
- 给定 配置包含五个有序步骤且相邻窗口为 30 分钟，存在完成前三步与完成全部步骤的会话；
- 当 看板按最近 7 天查询漏斗；
- 则 响应给出各步骤会话数、相对上一步与相对首步转化率以及流失数，同一步骤重复触发只计一次。

### AC-008 流失会话下钻
- 给定 第二步存在流失会话且另有会话在窗口外才到达下一步；
- 当 看板请求第二步的流失会话并查看其中一条的轨迹；
- 则 列表按最后到达时间倒序分页，轨迹按发生时间升序返回完整事件序列与属性。

### AC-009 概览粒度
- 给定 查询跨度分别为 36 小时与 10 天；
- 当 看板请求事件概览；
- 则 前者返回小时粒度时间点，后者返回天粒度时间点，且每个时间点含触发量与独立用户数。

### AC-010 体验指标与完整性
- 给定 库中存在性能、页面停留记录以及一个声明条数多于实际条数的批次；
- 当 看板请求性能、停留与完整性接口；
- 则 性能返回六项分位统计，停留返回分位数与分组，完整性返回缺失条数并列出不一致批次标识。

### AC-011 飞书登录一次性状态
- 给定 已生成一个有效的登录状态；
- 当 同一状态被并发回调两次；
- 则 只有一次回调完成登录并签发令牌，另一次返回状态无效。

### AC-012 应用凭据轮换
- 给定 管理员已创建一个应用且缓存中已有其密钥；
- 当 管理员轮换密钥并用旧密钥上报；
- 则 列表只显示新密钥掩码，旧密钥上报返回未知应用原因，新密钥上报成功。

## 12. 非功能需求

- **隔离**：写入池与查询池分离，默认上限分别为 10 与 5；查询 SQL 带数据库端最大执行时间提示，配置默认 5000 毫秒；进程可拆分为只写入与只查询两种模式。
- **性能**：日事件行数按不超过 20000 行设计，写入峰值低于每秒 20 次；7 天漏斗查询扫描行数低于 20 万行。
- **可观测性**：拒绝批次输出结构化告警日志；逐请求访问日志默认关闭；生产环境输出结构化 JSON 日志，开发环境带可读格式。
- **可用性**：启动失败时关闭数据库连接并退出；收到终止信号时先关闭服务再关闭连接池；就绪检查探测数据库连通性。
- **安全**：密钥明文入库、令牌只存摘要、签名使用恒定时间比较、跨域不允许携带凭据、查询接口以 Bearer 令牌鉴权。
- **容器化**：两阶段镜像基于精简系统，运行阶段只装生产依赖并以非 root 用户运行，暴露 8080 端口。

## 13. 依赖与风险

| 项 | 说明 |
| --- | --- |
| 运行时依赖 | Node.js 20 及以上、MySQL 8.0；依赖 Fastify、MySQL2、zod、yaml、pino、ua-parser-js |
| 部署依赖 | 数据库迁移需单独执行；上报独立域名与证书需部署侧提供；看板接口基地址与 SDK 静态路径需反向代理配置 |
| 验证风险 | 当前测试使用内存假库与 SQL 字符串断言，未连接真实 MySQL 执行迁移与查询 |
| 口径风险 | 性能分位统计与会话数统计的记录过滤条件目前不一致，分位查询未限制到最终阶段记录 |
| 多进程风险 | 限流计数与密钥缓存均为进程内内存，拆分多进程后额度按单进程计算，缓存失效不跨进程 |
| 能力缺口 | 数据保留期限、归档任务、按订单或会话删除、主动告警接口尚未实现 |
| 配置差异 | 漏斗配置文件中的应用标识与上层设计文档示例拼写不一致，需统一 |

## 14. 待确认问题

- 性能指标分位查询是否补加最终阶段过滤条件，使分位统计与会话数口径一致。
- 数据库查询超时是否需要增加应用层定时器，而不只依赖数据库端执行时间提示。
- 数据保留期限、按月归档与按订单或会话删除的实现时机与责任方。
- 三条基础告警指标的输出形式，是写库、打点还是接入现有监控系统。
- 漏斗配置文件中的应用标识拼写以哪一份为准，是否同步修正上层设计文档。
- 多进程部署时是否需要引入共享限流与共享缓存以替代进程内实现。
- 真实 MySQL 环境下的迁移与查询联调排期。
